# /validate ,  Pre-commit validation for any pivot or new bet

PURPOSE: Before building anything on a new idea, offer, or pivot, run it through a disciplined test with the kill number set in advance, so a failed test gets honored instead of rationalized. This exists because we once built for weeks on an unproven premise.

WHEN TO USE: Any time we consider a new direction. Run this before writing code or copy, not after.

STEP 1, FRAME THE BET (one short paragraph): the problem, who has it, the proposed solution, and why now.

STEP 2, SCORE THE BET. Rate each weak, medium, or strong with a one-line reason:
- Problem painful now, not someday. Is the pain felt today, or only anticipated.
- Who feels it acutely. The narrowest segment that hurts most.
- Willingness to pay now. Is there budget and ROI today, not in 18 months.
- In your control and provable. Can we deliver it and prove the result.
- Defensibility. What stops the platforms (Shopify, the AI engines) or incumbents from doing it for free.
- Founder fit and capacity. Does it match the skills and the hours available.
- Timing. Too early, right, or too late.

STEP 3, SET THE KILL NUMBER BEFORE TESTING. Write down the single metric and threshold that kills the bet, before any data is gathered. Example: fewer than 3 of 8 target customers call it a real near-term problem they would pay for.

STEP 4, RUN THE CHEAPEST TEST THAT MOVES THE NEEDLE. Usually 5 to 8 real customer conversations or one small real-world probe, never a full build. No building until the test passes.

STEP 5, HONOR THE RESULT. If it misses the kill number, kill it and log why. If it passes, take one small reversible step, not a full build.

HARD RULES:
- Set the kill number before you look at any results, and never move it after.
- Talk to real target customers, not the idea's fans.
- A clean kill is a win, because it saves the most expensive resource, which is time.
- Log the decision and the reason in PIVOT_LOG.md.

OUTPUT: the framed bet, the scored list, the pre-committed kill number, the test plan, and a DO, KILL, or DEFER recommendation.
